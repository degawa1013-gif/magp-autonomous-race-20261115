# 競技結果と保存走行記録の分析

## 1. 対象と競技段階の区別

本分析は、2026年11月14日および15日の開発・練習・予選に関する保存資料を対象とする。[大会公式結果ページ](https://minicar-autogp.org/race/04th_results/)からリンクされた公式集計表の「Q1 results」シートA16:I16では、NATC Tochigi（車両名Monovision_2、MAGPクラス）の記録は、予選1の非衝突周回3周・最速30.88秒、予選2の非衝突周回8周・最速25.23秒、MAGP/RR統合予選順位7位である。添付トーナメント図も、予選7位NATC Tochigiと予選2位YAXMの組合せを示す。この7位を「決勝総合7位」とは記さない。

決勝へ進出し初戦で敗退したことは、参加者本人の申告である。公式の決勝最終総合順位と初戦のスコアは未掲載・未照合である。結果と出典を `data/official_competition_results.json` に保存した。保存された261秒の連続AUTO区間と公式の予選2・8周を一対一に同定するスタートマーカーはなく、両者を直結して平均周回時間や完走率を計算しない。

詳細に分析できる長時間映像は、`qualifying_review_20261115_1137/` に保存された予選の記録である。これを決勝初戦の失敗映像と同一視しない。決勝初戦と保存ログの対応は未同定であり、決勝で生じた具体的な失敗原因は本ログから確定できない。

対象ディレクトリ内の元ZIPとJSONLを調査し、38セッション、13,987観測を集計した。58個の資料の読み取り時に、同じ時刻と処理フレーム番号をもつ観測を重複除外した。メタデータの内容が競合した観測は0件であった。ただし、これらは保存・回収できたセッションであり、実施した全試行の一覧ではない。短い停止場面、認識試験、途中から回収された分割記録も含むため、38を走行成功率の分母には使用しない。

根拠：`data/run_metrics.json` の `sources`、`sessions`、`duplicate_metadata_conflicts`。セッション別の集計は `data/session_metrics.csv` に保存した。再計算は `scripts/analyze_runs.py` で実行する。

## 2. 測定量の定義と計算方法

| 量 | 定義と限界 |
| --- | --- |
| 保存時刻 | `capture_time_unix_ms`。記録投入時の壁時計であり、露光開始時刻や衝突センサの時刻ではない。JSTへ換算した。 |
| 認識状態 | `metadata.mode` のTRACK、LOST、DEGRADED、STOP。車両の操作モードは別の `vehicle_control.mode` である。 |
| 状態サンプル率 | その認識状態の保存観測数を、対象区間の保存観測数で除した百分率。 |
| 状態推定時間率 | 保存観測の状態を次の観測まで左端保持し、その時間を合計した。1秒超の保存欠測間隔を除外し、最後の観測には時間を付与しない。これは保存間の未観測フレームを補間した推定値である。 |
| 画像誤差 | `raw_center_error`。画像変換後の制御点と目標位置の差で、単位はpxである。物理的な走行横偏差[m]ではない。LOST時に保持された値を現在の検出値と誤解しないよう、誤差統計はTRACK観測だけで計算した。 |
| 操舵指令 | `actuator_output.pi_steering.commanded_pulse_us`。出力ドライバに受理されたPWMパルス幅の指令であり、実舵角[deg]や物理波形の実測値ではない。予選では中立1530 µs、出力設定50 Hzである。 |
| 前進指令 | `corner_pace.applied_percent`。ソフトウェア上の出力率であり、スロットル設定値や車速とは区別する。 |
| 速度 | `encoder_speed_kph`。車輪の回転パルスから換算した値で、独立に測定した車体の対地速度ではない。空転、パルス欠落、換算係数の誤差を排除していない。 |
| カメラから出力までの時間 | `loop_timing.camera_to_output_ms`。カメラの `SensorTimestamp` とソフトウェアの出力処理後時刻の差である。PWM位相待ち、サーボ・ESC・モーターの機械応答を含む総合遅延ではない。 |
| 制御フレーム間隔 | `loop_timing.frame_interval_ms`。保存画像間隔とは別の、認識・制御側の処理フレーム間隔である。 |
| 分位点 | 昇順の値に対する位置 `(n−1)p` を線形補間して計算した。既存報告の切り捨て方式によるp95とは末尾数値がわずかに異なる。 |

予選の最終行までの保存間隔に1秒超の欠測はなかった。全区間の推定時間率の分母は261.070449秒である。部分区間の推定時間率の分母は、その区間内の保存観測の最初から最後までであり、名目上の60秒や30秒とは厳密には一致しない。

計測項目の実装箇所は、解析時点の `controller_hud_candidate/robust_lane_failsafe.py:3040–3058`（車輪換算値）および `:3544–3558`（時間計測）で確認できる。走行時バージョンの識別には、各観測に保存された `metadata.build` のSHA-256を優先する。

### 4.2 確認された事実・原因仮説・未検証事項

**確認された事実**：フレーム338–339の遠方点は目視上、同じ白テープの右カーブに沿っている。`ambiguous_branch` という診断文字列だけで別の物体を誤認したとはいえない。フレーム341–342では保存カメラ白マスクの非ゼロ画素が0になり、近傍点も消えた。LOST開始時には前進13%の指令が残り、その後に操舵指令は1530 µsへ戻った。車輪パルス数の不変区間でも前進指令は13–15%で継続し、フレーム380–384だけが15%であった。ここでの認識状態STOPは、車両の停止モードを意味しない。

**原因仮説**：カーブ接近時の姿勢と旋回応答に対し、近傍白線の認識継続が不足した可能性がある。白線が抽出領域の右下へ移動したことに加え、色被り対応条件と明度閾値の変化が抽出喪失に寄与した可能性がある。喪失後の操舵中立復帰と前進継続は、カーブ途中の回復を難しくした可能性がある。ただし、これらの寄与を分離した比較実験は実施していない。

**検証されていない事項**：実舵角、横加速度、ヨーレート、対地速度、車体位置、白テープからの実横偏差は取得していない。したがって、操舵指令不足と機械的追従不足を分離できない。出力信号が機器に到達しなかったこと、無線切断が接触の原因となったこと、遠方の分岐誤選択が原因となったことも、この記録だけでは立証できない。

## 5. ソフトウェアの手動入力遅延に関する保存実験

手動入力の処理と画像処理の分離に関する既存のPi上の比較実験が保存されている。これはevdev形式のイベントをパイプから注入し、模擬出力先が更新された時刻を測るソフトウェア試験である。Bluetoothの電波伝送、実GPIO、PWMの出力位相、サーボとESCの応答は含まない。各条件のイベント数は200件である。

| 条件 | 改修前の中央値 / p95 | 改修後の中央値 / p95 |
| --- | ---: | ---: |
| 画像処理負荷なし、パイプ送信→模擬出力 | 6.078 / 9.811 ms | 0.165 / 0.481 ms |
| 画像処理負荷あり、パイプ送信→模擬出力 | 6.663 / 10.322 ms | 0.380 / 1.661 ms |

この結果は、対象ベンチマークにおいて処理待ち時間が短くなったことを示す。会場での無線環境下の総合操作遅延が同じ割合で改善したとはいえない。負荷ありの試験では各測定中の画像処理回数が異なり、独立反復による信頼区間も記録されていない。

根拠：`manual_event_latency_review_20261115/benchmark_before_pi.json`、`benchmark_after_pi.json`、`benchmark_before_load_pi.json`、`benchmark_after_load_pi.json`。集計と各資料のSHA-256は `data/run_metrics.json` の `saved_software_latency_benchmark`、表形式は `data/manual_software_latency_benchmark.csv` に保存した。

## 6. 次回の評価設計

1. 決勝・予選・練習の競技段階、車両識別、開始終了、公式周回数と記録セッションIDを同じ実験台帳に残す。これにより、決勝の失敗を予選ログから説明する取り違えを防ぐ。
2. 同じコース・速度設定・照明条件を固定し、近傍認識の改善、遠方先読み、喪失時方策を一つずつ比較する。完走または逸脱の判定基準と全試行数も事前に定義する。
3. 実舵角または車体姿勢を測定し、カメラ時刻・操舵指令・実応答を同じ時計で比較する。画像誤差から実横偏差へ換算する場合にはカメラ校正と地面平面の検証を行う。
4. 会場での操作遅延は、無線受信より前の入力基準時刻から物理応答までを測る。現在のソフトウェアベンチマークと無線診断を分けて評価する。
5. 接触・逸脱の注釈、コース位置、機械状態、ログの欠測を保存する。これらが得られるまで、画像から推定した接触時刻をミリ秒精度の衝突実測値として扱わない。

再現コマンド：`python3 reports/scripts/analyze_runs.py --base /path/to/magp-recovery`。元データを変更せず、解析結果だけを `reports/data/` に再生成する。図表はこれらのCSVとJSONから作成できる。

次回の同形式の保存データには、例えば `python3 reports/scripts/analyze_runs.py --base /path/to/project --reviews next_event_review --inventory-only --out reports/data/next_event` を使用する。この汎用モードは新しいセッションの集計までを行い、競技段階や接触位置を推測しない。接触の注釈は、次回の画像と競技台帳を照合して別途与える必要がある。予選ディレクトリだけを対象にした汎用モードの実行では、4セッション・2049観測の集計を確認した。
