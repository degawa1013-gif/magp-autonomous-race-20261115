# 走行資料と主張を結ぶための読み方

保存形式が異なる場合は実ファイルの列・単位に合わせる。この文書は不足する値の補間や新しい実験の代替ではない。

## 主張に付ける最小限の根拠

| 主張の種類 | 残す情報 |
|---|---|
| 実装・設定 | ファイルの相対パス、SHA-256、該当関数／行、記録中のbuild情報、配布記録との一致・不一致 |
| 走行数値 | 競技段階・セッション、入力パスとハッシュ、対象範囲、算式、分母、単位、重複・欠測・除外規則、再実行コマンド |
| 場面・接触 | 同期キー、画像のパス、記録時刻と経過時刻の基準、目視で確認した現象、確定できる時刻幅 |
| 成績 | 公式ページ・表の欄名・確認日、チーム識別、当事者の説明と公式記載の一致／差分 |
| 継承・改善 | 比較する両版、差分、採用の証拠、比較条件。保存コードの存在と実走採用を分ける |
| 仮説・不足 | 何を観測したか、考えられる機構、必要な追加観測。仮説を結論へ昇格させない |

Gitは `git cat-file -t` 等で対象の型も確認する。treeはファイル集合を示すが、commitの作者・日時・親・変更メッセージを持たない。HEADのないリポジトリや未追跡ファイルには通常のコミット時系列を付けない。

## この保存形式で取り違えやすい項目

| 項目 | 参照例 | 解釈 |
|---|---|---|
| 運転モード | `metadata.vehicle_control.mode` | AUTO、MANUAL、STOP等。画像認識の状態とは別 |
| 知覚状態 | `metadata.mode` | TRACK、LOST、DEGRADED、STOP。知覚STOPだけでは駆動停止を意味しない |
| 画像上の誤差 | `metadata.raw_center_error` | 変換後画像のpx値。距離校正と幾何条件なしに横偏差[m]へ換算しない。LOST中に保持した誤差を現在の検出値に数えない |
| 操舵指令 | `metadata.actuator_output.pi_steering.commanded_pulse_us` | 出力ドライバに受理された指令[µs]。実端子の波形・実舵角[deg]とは別 |
| 出力割合 | `metadata.corner_pace.applied_percent` 等 | 指令の相対量[%]。速度[km/h]やモーターの機械出力[W]ではない |
| 車輪換算速度 | `metadata.encoder_speed_kph` | 直径・パルス数・scaleに依存。空転・ギア・校正を確認し、独立した実車速度と呼ばない |
| 処理時間 | `metadata.loop_timing.*` | 各コードの時計・境界を確認する。カメラ→指令と、Bluetooth操作→実舵角は異なる測定 |
| 実行版 | `metadata.build.source_sha256` | 保存ソース・配布記録と一致させる。別系列のソースや最新の作業ファイルで置換しない |

フィールドの実体は `reports/scripts/analyze_runs.py` の `reduced()` と元JSONLで照合する。CSVにある `odom_x_m` 等は、列名だけでSLAMや独立した位置計測の証拠にならない。

## 集計と時間

- アーカイブ・展開物・metadataコピーで同じ観測を二重計上しない。既存解析は `capture_time_unix_ms` と `metadata.frame_index` を照合する。重複内容が食い違う場合は競合を残す。
- TRACK率は内部状態の割合であり、白線の正解ラベルに対する精度・コース内走行率・完走率ではない。走行成功率には試行の総数と成功判定が必要である。
- サンプル率と推定時間率を分ける。既存集計の時間率は隣の観測まで左側の状態を保持し、1秒超の記録欠測は除外、最後の観測は0秒重みである。変更する場合は理由と分母を明示する。
- 保存fps、制御ループ間隔、カメラ更新fpsを区別する。間引いた保存観測から全制御周期の分布を作らない。
- 接触時刻は画像から確認できる範囲で示す。最初の保存AUTO観測はモード移行そのものの時刻と同じとは限らない。未保存区間の完走・接触を推定しない。

## 無線データ

`pico_radio_monitor_20261115/` と車載診断を併用する場合は、次を確認する。

- **観測点**：PicoのAP検出はPC近傍、Piの接続先RSSIやBluetooth診断は車載側であり、同じ地点の測定として合成しない。
- **更新・キャッシュ**：同じping結果やBluetooth診断を複数回保存したスナップショットがある。診断件数を独立した送受信試行数とせず、timeout件数からパケット損失率を作らない。
- **単位**：Wi-FiのRSSI[dBm]、Bluetooth Classicの相対RSSI、Link Quality、AFHで有効な候補数は別指標である。0・負値・欠測を一律に「電波なし」と読まない。
- **観測範囲**：AP数とチャンネル幅からの重なり推定は、実測スペクトラム・帯域占有率・干渉率ではない。RSSI単独からAPまでの距離を算出しない。
- **期間・時計**：予定終了時刻と最後に得た観測時刻を区別する。PC受信時刻とPi時刻の差を同期確認なしに操作遅延と呼ばない。欠測は線を切る等で残す。
- **原因**：無線指標の悪化と車両の応答・衝突が近い時刻でも、運転モード、ソフトウェア負荷、実出力、無線の測定境界を確認するまでは原因を断定しない。
