# 自動走行競技の技術報告

このSkillは競技資料から根拠を組み立てる部分を担当する。論文一般の構成・文章・工程は、利用可能な `sciwrite-manuscript`、`sciwrite-prose`、`sciwrite-process` に委ねる。指定された言語・章立て・投稿様式を優先する。

## 対象と版を固定する

1. ユーザー指定のプロジェクトと報告書ディレクトリを特定し、既存の `source_inventory.md`、`verification.md`、設定ファイルがあれば読む。パスが変わっていても、このSkillの設置場所を車両ソースの場所と推定しない。
2. 競技名・日付・段階（練習／予選／決勝）、チーム、対象セッション、採用設定を根拠付きで区別する。段階が未同定の記録は未同定のまま解析する。
3. 実行時のソースハッシュ、保存ソース、配布記録を照合する。フォルダ名の `candidate`、更新日時、Git treeの存在だけで採用・変更順を決めない。Gitのcommit、tree、blob、未追跡の作業ファイルを区別する。
4. ログの単位・同期・重複・欠測を [evidence_schema.md](references/evidence_schema.md) で確認する。2026年11月のMAGP資料を扱う場合だけ [project_profile.md](references/project_profile.md) を読む。そこにある値・順位・失敗注釈を次大会へ流用しない。

## 既存の解析・作図を再利用する

報告書ルートにあるスクリプトを先に調べ、同じ集計を別実装で増やさない。この配布では `reports/scripts/` が対応する。設定ファイルや `--help` がある場合は現在の引数を確認し、以下の役割で選ぶ。

| ファイルがある場合 | 用途・境界 |
|---|---|
| `scripts/inventory_sources.py` | ソース・資料の存在とハッシュ一覧を再生成。対象rootとDownloads許可リストを確認する |
| `scripts/analyze_runs.py` | 次大会の新しい記録には `--base`、明示した `--reviews`、別の `--out` と **`--inventory-only`** を使う。この版の既定実行には今回の予選固有注釈がある |
| `scripts/make_figures.py` | 対応する集計JSON/CSVがある場合に図を再生成。現在の必須入力とスキーマを確認し、今回固有の時系列を別大会の結果として描かない |
| `scripts/rebuild.py` | 存在し、設定・引数・出力範囲を確認できれば、論文一式の再生成に使う |
| `scripts/verify_report.py` | 存在すれば、本文・数値・引用・図表・実装参照の検証に使う。実際に検査した範囲も記録する |

新規記録の集計例（レビュー名と出力先は対象大会に合わせる）：

```bash
python3 reports/scripts/analyze_runs.py --base /path/to/project \
  --reviews next_event_review --inventory-only --out reports/data/next_event
```

次大会では派生CSVだけでなく原JSONL/ZIPも保存する。派生CSVしかない場合は列と型を確認して既存の `summarize()` 相当の集計へ接続し、原画像・原JSONL・版照合を再検証できていない範囲を残す。

スクリプトがない場合は、このSkillの導入や車両への接続を前提にせず、利用可能な原資料から同じ根拠形式で進める。新しい解析コードが必要なら報告書側に置き、条件・単位・除外規則と再実行方法を残す。

## 原稿へ接続する

- 先に確定した図表と根拠台帳を `sciwrite-manuscript` に渡す。実装説明は該当ソースの版・箇所へ、数値は入力ハッシュと計算方法へ対応させる。既存資料からの継承と今回の変更を分ける。
- `sciwrite-process` で収集・草稿・レビューを分離し、`sciwrite-prose` で主張と数値を維持して推敲する。日本語に対する英語正規表現の監査結果だけで校閲済みとしない。外部Skillが未導入なら執筆を継続し、導入の必要性は別途整理する。
- 先行研究は採用または明示的に区別した探索実装に限って調べ、原典の内容・DOI・URLを確認する。モデル名の一般解説を実装の証拠に代用しない。
- 観測事実、原因仮説、未検証事項を分ける。`[要確認]` は確認対象を具体的にし、未実施実験・対照条件・完走数を補わない。
- 仕上げは根拠不足と数値の問題を優先して修正し、PDF等は対応する既存制作Skillで描画確認する。Markdown、BibTeX、図表、解析コード、検証記録を指定の報告書フォルダへ保存する。

この処理は保存資料の解析と報告書作成である。競技プログラムの変更・実車出力・Gitコミット・外部公開・Skillの有効化は含まない。環境変更が必要になった場合は、ユーザーの導入方針に従い、具体的な変更内容を提示してから扱う。
